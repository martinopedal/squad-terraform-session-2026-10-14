# Starter safety profile

Historical starter provenance is Squad CLI 0.13.0; the installed session baseline
is Squad 1.0.1. This page describes the retained narrow adaptation for the
conference's human-reviewed workflow, not a claim that current runtime is 0.13.0.

Audience: maintainers inspecting starter provenance. [The repo map](repositories.md)
and [four-lane progress](sandboxing.md#october-12-progress-and-next-actions)
separate this public teaching configuration from deployment and runtime. Tool
profiles/Squad configuration do not isolate credentials. Local MXC startup is
currently policy blocked; native separate Online deployment/access/base is
independently verified. Corrected ACA SANDBOXES host runtime passes; acceptance
complete, then runtime-ready. Stage GO and hosted Apps/Jobs E2E remain separate.
Host Copilot/Squad remote orchestration and optional in-MicroVM runtime need
different actual evidence; neither follows from starter setup.

The active and template copies of `cross-squad-communication` use an operator-led Plan-mode invocation instead of blanket tool/path approvals. Their upstream prototype results are historical; they do not validate this modified recipe.

The optional `e2e-template-testing` template is omitted because its unattended blanket-approval recipe is outside this demo. No other published starter file directly references that template. Peer discovery and communication remain available; unattended peer execution is not enabled.

Upgrading or regenerating starter files may restore upstream instructions. Review the resulting diff and permission guidance before using it. Do not assume repository instructions, tool availability, tool approval, and operating-system isolation are equivalent.

Third-party attribution is retained in `THIRD_PARTY_NOTICES.md`. These local choices describe this demonstration, not a claim that all Squad installations have identical policies or behavior.
