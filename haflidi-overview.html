How we got to a secure, well-aligned cluster

This is the short path. The table says where Squad and GitHub Copilot helped, and what a human still decided.

Step What was built Who/what helped What the human decided
1. Private-by-default contract A Terraform module boundary where the module owns resources, inputs, outputs, and provider requirements, while the caller owns provider, backend, auth, state, and environment values. Squad coordinated responsibilities and one owner per shared surface. Copilot CLI Plan mode was used before edits. The terraform-coder lane was the writer lane for bounded Terraform changes. The human approved the repo-only plan and kept the boundary clear before implementation.
2. Tests and repeatable checks Contract tests, a deliberate mutation-and-repair loop, and a repeatable prompt path for the main demo. The terraform-validator lane ran the fixed offline checks. The terraform-reviewer lane reviewed the exact diff in a fresh context. The current repeatability checkpoint is B1v2 5/5, B2 5/5, and B3 4/5. The human decided which brief to trust for the live story, kept the oracle rules visible, and accepted only a specific reviewed artifact.
3. GitHub security and review controls A pull-request path with scans and review on the module and consumer repos. GitHub controls provide CodeQL, secret scanning with push protection, Dependabot security updates, protected main, and required review. The security appendix says AI also found silent gaps that scanners did not raise as alerts. The human still reviewed the real change, kept the remaining gaps visible, and decided what was acceptable to merge.
4. Approved pipeline delivery A gated deployment path from reviewed code to Azure through the consumer repo. GitHub OIDC provided Azure access without a stored cloud secret. Squad records the reason for later handoff, and the talk track shows Scribe merging accepted public decisions into the shared decision ledger. Microsoft Learn through MCP supplied product rules such as Base-to-Automatic migration not being supported. The human approved the environment gate, compared the plan, and decided when Azure writes were allowed.
5. Runtime proof The cluster and the public page AKS Automatic | NIC 2026 demo. The runtime check step fails unless the hostname returns HTTPS 200, HTTP redirects, and DNS resolves to the App Routing controller Service address. The current Online read-back result is 29/29 PASS. The human decided that runtime evidence, not local success alone, was the acceptance point for the deployed outcome.

Deterministic prompts, and the alternative

Deterministic prompts help us replay how we got there. The current eval in docs/determinism-eval.md is B1v2 5/5, B2 5/5, and B3 4/5.

That gives us a stable path for the main story. It lets Haflidi see what is supposed to happen and why.

That path already uses an agent, a skill, and /mcp for the Terraform and documentation grounding story. It stays small and easy to explain.

Model choice and cost

Auto model selection in Copilot CLI routes by task, lets us switch with /model, honors admin model policies, and gives paid plans a 10% AI-credit discount in Auto.

Project HydraFusion is a research preview with Single, Cascade, and Critique patterns; GitHub reports offline benchmark cost savings versus Opus 5.

For our repeatability eval, we pinned claude-sonnet-5.
